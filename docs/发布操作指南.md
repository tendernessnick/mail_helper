# 发布操作指南（维护者手册）

> 本指南描述 MailHelper 从改代码到用户「点开就能下载、应用内一键更新」的完整链路。
> 发布链路技术方案：Velopack + GitHub Releases（08 章 §4.3，S15 落地）。

## 一、整体架构：一次打 tag，发生了什么

```
开发者打 tag v0.4.0 并推送
        │
        ▼
GitHub Actions（ci.yml release job）
  1. build-test：全量测试 + 覆盖率门禁（Core ≥ 80%）——不过不发版
  2. 版本 = tag 去掉 v 前缀（0.4.0），dotnet publish 自包含 win-x64（-p:Version 注入）
  3. vpk pack：产出 Setup.exe、便携版 zip、完整/增量更新包（.nupkg）、releases.stable.json
  4. 生成 SHA256SUMS.txt
  5. vpk upload github：创建正式 GitHub Release 并上传全部产物
        │
        ▼
用户侧两种获取方式
  · 网页：仓库 Releases 页（releases/latest 永久指向最新正式版）
  · 应用内：设置 → 关于 → 检查更新（UpdateManager 经 GithubSource 拉取 releases.stable.json 比较版本）
```

push 到 main 不打 tag 也会构建发布，但走 **beta 渠道**：版本为 `基线-beta.构建号`（如 `0.4.0-beta.42`），GitHub 上标记为 Pre-release，**不影响** Releases/latest，也**不会推送**给应用内检查更新的用户（应用只认正式版）。

## 二、版本策略

| 位置 | 值 | 作用 |
| --- | --- | --- |
| git tag `v*.*.*` | **发版时你打** | stable 版本唯一事实源，CI 读取并以 `-p:Version` 注入编译 |
| `Directory.Build.props` 的 `<Version>` | 下一版基线（如 0.5.0） | 本地构建显示的版本；beta 渠道版本 = 此值 + `-beta.构建号` |
| `src/MailHelper.App/Updates/UpdateService.cs` 的 `RepoUrl` | 仓库 URL | 应用内更新源；**换仓库/改用户名时必须同步改** |

规则：

- 版本号遵循语义化：功能新增进位次版本（0.4.0 → 0.5.0），缺陷修复进位末位（0.4.0 → 0.4.1）。
- tag 一旦发布不要删除/重打——已装用户靠版本号单调递增判断更新。
- 同一 tag 重跑 CI 无副作用：`vpk upload github --merge` 会把产物合并进既有 Release。

## 三、标准发版流程（例行操作）

```bash
# 1. 确认 main 全绿：https://github.com/tendernessnick/mail_helper/actions
#    （main 的最近一次 push 应已自动产出 beta 预发布，可先手动装 beta 验证）

# 2. 更新版本基线与 CHANGELOG
#    - Directory.Build.props：<Version>0.5.0</Version>
#    - CHANGELOG.md：补 0.5.0 条目（用户可读文案，08 §5 检查单第 3 项）

# 3. 提交并推送
git add -A && git commit -m "chore(release): v0.5.0" && git push

# 4. 等 CI 全绿后打 tag 发正式版
git tag v0.5.0 && git push origin v0.5.0

# 5. 验证（约 10–15 分钟后）：
#    - Actions 页 release job 绿
#    - https://github.com/tendernessnick/mail_helper/releases/latest
#      标题应为 MailHelper v0.5.0，含 Setup.exe / portable.zip / SHA256SUMS.txt / .nupkg / releases.stable.json
#    - 已装旧版的应用内「检查更新」应提示新版本
```

## 四、应用内更新机制（S15）

- 入口：设置 → 关于 → 「检查更新」。
- 实现：`Updates/UpdateService.cs` 用 `UpdateManager(GithubSource(RepoUrl, prerelease: false))` 检查 → 后台下载（进度显示）→ 用户点「重启并安装更新」→ `ApplyUpdatesAndRestart` 由 Velopack 接管退出/替换/拉起。
- 更新包支持增量（delta）：多数小版本只下载差异部分。
- 源码/裸 exe 运行（非 Velopack 安装）时入口自动禁用，避免误报。
- 设置页文案「仅接收正式版」与 `prerelease: false` 对应：beta 预发布永远不会弹给最终用户。

## 五、排障

| 现象 | 处置 |
| --- | --- |
| release job 失败于 vpk upload | 看 Actions 日志；多为 token 权限（需 `permissions: contents: write`）或同 tag 冲突（`--merge true` 已兜底）；失败时产物已作为 workflow artifact 保留 |
| 应用内「检查更新失败」 | GithubSource 匿名访问限 60 次/小时/IP；多为网络问题，重试即可 |
| 用户装了 beta 想回正式版 | 直接从 Releases/latest 重装 Setup.exe 即可（版本号降级需覆盖安装，非应用内更新） |
| SmartScreen 拦截 | 未签名程序的正常提示：更多信息 → 仍要运行；发布页随附 SHA256SUMS.txt 供校验 |
| Win10 缺 WebView2 | 应用依赖 WebView2 Runtime（Win11 内置）；缺失时从 https://developer.microsoft.com/microsoft-edge/webview2/ 装 Evergreen Runtime（`installer/MicrosoftEdgeWebview2Setup.exe` 即其离线包，不入库） |

## 六、历史与退役说明

- v0.3.1 及之前：Inno Setup（`installer/MailHelper.iss`）出安装包，**无应用内更新**；产物手工放入发布物。
- v0.4.0 起：**Inno Setup 退役**，Velopack 全面接管安装包 + 便携版 + 自动更新。`.iss` 脚本保留在 git 历史中可随时找回；`installer/` 目录仅留 WebView2 离线安装器（本地，不入库）。
- 此前由 Inno Setup 安装的存量用户：应用内检查更新不可用（非 Velopack 安装），请从发布页重装一次 v0.4.0+ 完成迁移，此后即可持续自动更新。
