### 3.3 迁移与重建策略

- EF Core `__EFMigrationsHistory` 管理 schema 演进；规则表变更必须向后兼容（只增列）。
- 启动时 `PRAGMA integrity_check`：失败 → 备份旧库为 `mailhelper.corrupt.bak` → 重建 schema → 保留 `rules`（规则独立 JSON 兜底导入）→ 触发全量重同步（EX-07）。
- 连接串参数：`Mode=ReadWriteCreate;Cache=Shared;Pooling=true`，`PRAGMA journal_mode=WAL; synchronous=NORMAL`。

## 4. 外部接口设计

### 4.1 Graph 调用清单（唯一出口 `GraphMailProvider`）

| # | 调用 | 权限 | 说明 |
| --- | --- | --- | --- |
| G-1 | `GET /v1.0/me` | User.Read | 登录后校验账户 |
| G-2 | `GET /v1.0/me/mailFolders?$top=50` | Mail.Read | 初始化：定位 Inbox folder id |
| G-3 | `GET /v1.0/me/mailFolders/{id}/messages/delta?$select=...&$top=100` | Mail.Read | 核心：增量/全量同步；`$select=id,internetMessageId,subject,from,receivedDateTime,isRead,hasAttachments,bodyPreview,body,changeKey` |
| G-4 | `GET {nextLink}` / `GET {deltaLink}` | — | 分页与断点 |

**要点**：
- 全量判定：`sync_state.delta_link` 为空 → 直接调 delta（不带 deltaToken），Graph 返回全量分页。
- 正文获取：全量阶段 `$select` 不含 `body`（提速），仅存 `bodyPreview`；用户点开某封邮件时按需 `GET /messages/{id}?$select=body` 单封拉取并写磁盘缓存（命中则跳过）。**例外**：P0 候选邮件同步时即拉正文（截止时间正则需要正文）。
- 删除语义：delta 响应含 `@removed` → 本地 `is_deleted_remote=1`，默认列表隐藏，设置项「清理 90 天前已删记录」。

### 4.2 限流与重试

| 情形 | 处理 |
| --- | --- |
| HTTP 429 | 读取 `Retry-After`（秒）休眠后重试，最多 3 次；仍失败则本轮终止，状态 `Error(Throttled)` |
| 5xx / 网络异常 | 指数退避 2s/8s/30s；失败本轮终止 |
| 401 | MSAL 静默刷新令牌一次后重试；再失败 → `ReauthRequired` |
| 批次幂等 | upsert 以 `messages.id` 为主键；重复同步不产生重复行（FR-04 AC2） |

### 4.3 IMAP 兜底（`ImapMailProvider`）

- 服务器 `outlook.office365.com:993` SSL；认证 `SASL XOAUTH2`（用户名 + Graph 域令牌，scope 需 `https://outlook.office365.com/IMAP.AccessAsUser.All`）。
- 增量：按文件夹记录 `UIDVALIDITY` 与最高 `UID`；`UID SEARCH UID {watermark+1}:*` 拉取。
- 限制：感知不到远端删除/移动（v1.0 接受，见 03 §5.4）；`Fetch(ENVELOPE|BODYSTRUCTURE|BODY[HEADER|TEXT])` 组装 `RemoteMessage`。

## 6. 日志规范（Serilog）

- 输出：滚动文件 `%AppData%\MailHelper\logs\mailhelper-.log`（日切，保留 14 天，单文件 10MB 上限）+ Debug 级仅诊断模式开启。
- 结构化字段：`event`、`account_id`、`provider`、`latency_ms`、`batch_size`、`err_code`。
- **脱敏红线**：不记录邮件正文与主题全文（主题截断 40 字符 + hash）；不记录令牌；发件人地址保留域名（诊断需要时开诊断模式才完整记录）。
- 关键埋点：`sync.completed`（页数/耗时/新增/更新/删除）、`classify.completed`（各类别分布、待确认数）、`notify.sent`。

## 8. 通知决策细节（MOD-07）

1. 同步完成事件携带 `newMails`；过滤 `Importance >= P1` 且 `NOT EXISTS(notification_log)`。
2. P0：逐封 Toast；P1：若 ≥3 封则聚合为「x 封重要邮件」摘要，否则逐封。
3. 勿扰时段命中 → 写入 `notification_log(level=queued)`，时段结束后补发摘要。
4. 通知去重键：`message_id`；重复同步不会重复通知（FR-14 AC2）。

### 10.5 触发与去重语义
