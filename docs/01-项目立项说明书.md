## 1. 项目背景

### 1.1 问题陈述

内地学生获得香港高校录取后，学校会开通 Office 365 学生邮箱（`@connect.hku.hk`、`@link.cuhk.edu.hk`、`@connect.ust.hk` 等）。在整个就读周期内，该邮箱是学校与学生之间**唯一的官方通信渠道**，邮件量巨大且高度混杂：

| 邮件来源 | 典型内容 | 特征 |
| --- | --- | --- |
| 教学系统（Moodle / Canvas / Blackboard） | 作业发布、截止提醒、成绩公布 | 学期中高频，有硬性截止时间 |
| 各院系、各课程教师 | 课件通知、调课、答疑安排 | 发件人分散，格式不一 |
| 就业中心（Careers Centre） | 实习/全职岗位、简历（CV）工作坊、招聘会 | 求职季高频，时效性强 |
| 注册处 / 教务处 | 选课、注册、毕业审核、成绩单 | 数量少但极其关键 |
| 财务处 | 学费账单、缴费截止、逾期警告 | **错过会产生滞纳金甚至影响学籍** |
| 签证/入境事务相关 | 签证材料、Visa Label、IANG 提醒 | **错过影响合法性居留** |
| 图书馆、IT 服务、学生事务处 | 到期提醒、系统维护、活动通知 | 中频、低风险 |
| 订阅与自动通知 | 各类系统自动回执、社团邮件列表 | 纯噪音 |

### 1.2 核心痛点

1. **混杂难寻**：所有邮件涌入同一个收件箱，学生需要在数百封邮件中人工翻找重点。
2. **错过代价高**：学费缴纳截止、选课截止、签证材料提交等邮件一旦错过，会产生金钱损失、影响选课甚至学籍与合法居留。
3. **现有工具不适配**：Outlook 自带的「聚焦收件箱」基于通用商业邮件模型训练，不理解港校场景；自建 Outlook 规则要求用户熟悉规则语法且维护成本高；学生没有时间与动力做精细的邮箱管理。
4. **跨设备割裂**：手机通知嘈杂导致学生关闭通知，进一步加剧重要邮件被忽略。

### 1.3 机会

港校学生群体规模稳定（八大校内地学生约数万人/年），痛点同质化程度高，邮件来源（LMS、行政部门发件人）高度可归纳，**用一套可维护的规则引擎即可覆盖绝大多数分类需求**。以本地桌面工具形态交付，无需服务器，无持续运营成本。

## 2. 项目目标与成功指标

### 2.1 项目目标

1. 提供一个 Windows 单文件 exe 应用，学生安装后登录自己的学校邮箱即可使用，无需任何服务器部署。
2. 程序在后台**定时增量同步**邮箱新邮件，自动完成**类别分类**与 **P0–P3 重要程度标记**。
3. 提供清晰的三栏浏览界面与重要度过滤，使学生「打开软件 10 秒内看到今天必须处理的事」。

### 2.2 成功指标（可量化验收）

| 指标 | 目标值 | 度量方式 |
| --- | --- | --- |
| 分类准确率（7 类别） | ≥ 85%（基于标注样本集） | 测试计划 §分类器评估 |
| 紧急邮件（P0）召回率 | ≥ 95%（不允许漏标学费/签证类截止） | 同上 |
| 查找重点邮件耗时 | 相比在 Outlook 中人工翻找降低 ≥ 50% | UAT 任务计时对比 |
| 初次同步性能 | 5000 封存量邮件 ≤ 2 分钟 | 性能测试 |
| 冷启动到可用 | ≤ 3 秒 | 启动计时 |
| 崩溃率 | 会话崩溃率 < 0.5% | 本地崩溃日志统计 |

### 2.3 非目标（明确不做）

- 不做邮件发送、代回复、代删除远端邮件（首版本地只读缓存 + 标记同步；删除远端列入后续评估）。
- 不做服务器端存储或账号体系——**邮件数据不出本机**（LLM 扩展除外，见 09 安全与合规）。
- 不做 macOS / Linux / 移动端。
- 不替代学校官方通知渠道，仅做组织与提醒辅助。

## 3. 目标用户与画像

| 画像 | 描述 | 核心诉求 |
| --- | --- | --- |
| **P1 新生小林**（授课型硕士，入学 0–3 个月） | 刚拿到 Visa Label，正在办注册、选课、交学费；邮箱每天涌入 20+ 封邮件，分不清哪些必须立即处理 | 「别让我错过截止日期」：P0 级提醒、账单类置顶 |
| **P2 求职季阿哲**（研二，投递实习/全职） | 每周收到几十封 Careers Centre 与招聘系统邮件，还要盯面试邀约 | 「把职业发展类单独拎出来」：类别过滤 + 快速标记已处理 |
| **P3 博士生学姐 Wang**（在读 3 年，邮箱存量 2 万封） | 历史邮件堆积如山，从不整理，但要快速定位某封历史邮件 | 「存量也能用」：初次全量同步 + 本地全文搜索 |

## 4. 范围定义

### 4.1 本期范围（In Scope）

- OAuth 2.0 连接学校 Office 365 邮箱（多租户，兼容各港校租户）。
- Graph API 增量同步（delta query），可配置同步间隔（1–60 分钟，默认 5 分钟）。
- 本地规则引擎自动分类：7 大类别 × P0–P3 重要程度。
- 三栏浏览界面、重要度/类别过滤、本地全文搜索、HTML 邮件沙箱渲染。
- 手动纠正分类并反哺规则权重。
- 自定义规则编辑器（发件人 / 关键词 / 正则）。
- P0 邮件 Windows 系统通知；托盘常驻、可选开机自启。
- IMAP XOAUTH2 兜底通道（个别租户限制 Graph 时）。

### 4.2 非本期范围（Out of Scope，列入演进路线）

| 功能 | 说明 |
| --- | --- |
| 多账户管理 | 多学校账号/个人账号同时接入（V2.0 候选） |
| LLM 智能分类 | 通过 `IClassifier` 扩展点接入大模型（需用户明示同意，见 09） |
| 远端写操作 | 在本工具内删除/归档/移动远端邮件（V2.0 评估） |
| 聚合摘要/日报 | 每日重要邮件摘要（V2.0 候选） |

## 5. 竞品与替代方案分析

| 方案 | 优点 | 不足 → 本项目机会 |
| --- | --- | --- |
| Outlook 自带「聚焦收件箱」+ 规则 | 零安装，官方功能 | 模型面向通用商务邮件，不识别港校 LMS/行政发件人；规则需自行编写且无法跨设备理解语境；无 P0–P3 分级概念 |
| Outlook 分类标签 + 搜索文件夹 | 官方、可同步 | 仍需人工逐封标记，无自动分类；移动端体验差 |
| eM Client / Mailbird 等第三方客户端 | 界面组织能力强 | 通用客户端，无垂直场景分类模型；付费；重量级 |
| 自写 Python 脚本（部分学生 DIY） | 灵活 | 门槛高、无界面、无定时守护、不可分发 |
| **MailHelper（本项目）** | 港校场景专用的类别/重要度模型；规则可解释可定制；本地数据不出机；免费、单文件即装即用 | 需要解决租户授权风险（见 §7 与 RISK-01） |

**结论**：市面上不存在针对港校学生邮箱场景的专用管理工具，本项目填补该空白，且以「规则引擎 + 本地优先」控制实现与维护成本。

## 6. 可行性分析

### 6.1 技术可行性

| 关注点 | 评估 | 结论 |
| --- | --- | --- |
| 邮箱接入 | 港校学生邮箱均为 Exchange Online，Graph API `Mail.Read`（委托权限）即可读取；桌面端 OAuth 2.0 + PKCE 为微软官方推荐路径；MSAL.NET 与 Microsoft.Graph SDK 为一等公民支持 | ✅ 成熟 |
| 增量同步 | Graph delta query 官方支持，`deltaLink` 可持久化断点续传 | ✅ 成熟 |
| 自动分类 | 邮件来源规律性强（LMS、行政部门发件人域名固定），规则引擎可解释、零训练成本；预留 `IClassifier` 接口保障演进空间 | ✅ 可控 |
| Windows exe | .NET 8 支持自包含单文件发布；WPF 为微软长期支持的原生 UI 框架 | ✅ 成熟 |
| 主要技术风险 | 学校租户可能禁用「用户同意第三方应用」（RISK-01） | ⚠️ 有缓解方案（自有 Azure 应用注册指引 + IMAP 兜底），不阻塞立项 |

### 6.2 经济可行性

- 纯本地应用，无服务器、无带宽、无存储成本。
- Graph API 委托权限免费（用户访问自己的邮箱）。
- 开发成本：1–2 名工程师 × 约 10 周（见 07 项目计划）。
- 唯一潜在成本：代码签名证书（可选，见 08）；LLM 扩展若启用由用户自备 API Key。

### 6.3 操作可行性

- 目标用户为研究生群体，具备「下载 exe → 登录学校账号」的基本操作能力。
- 首次运行提供 Onboarding 向导；分类规则开箱即用（内置港校预置规则包），无需用户配置即可获得 80% 以上价值。
- 数据完全本地化，隐私顾虑低（详见 09）。

### 6.4 法律与合规可行性

- 应用以「用户授权访问自己的邮箱」模式运行，属微软 Graph 允许的委托访问场景；需遵守微软平台政策与香港 PDPO（详见 09 安全与合规）。
- 产品命名与界面需避免暗示与微软官方关系（商标合规）。

## 8. 关键假设与依赖

| 编号 | 假设 / 依赖 | 若不成立的影响 |
| --- | --- | --- |
| A-01 | 港校学生邮箱持续托管在 Exchange Online | 高：接入层需重做（可能性极低） |
| A-02 | 目标租户允许用户同意第三方应用，或用户可完成自有应用注册 | 高：触发 RISK-01 缓解预案 |
| A-03 | 用户 Windows 10 19041+ / Windows 11，可安装 WebView2 Runtime | 中：安装包需捆绑 WebView2 引导 |
| A-04 | 用户愿意授予 `Mail.Read` 委托权限 | 高：产品前提不成立 |
| A-05 | 分类知识（发件人/关键词）可由少量样本快速归纳 | 中：影响冷启动准确率 |

## 9. 立项结论与建议

**结论：建议立项。** 痛点真实且同质化，技术路径成熟，无服务器成本，1–2 人团队 10 周内可交付 MVP 至正式发布。最大外部风险为租户授权策略（RISK-01），已在架构中内置 IMAP 兜底与自助注册预案，不构成阻塞项。
